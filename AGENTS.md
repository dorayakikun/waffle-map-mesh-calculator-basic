# AGENTS.md

Project instructions for AI coding agents (Claude Code, Antigravity / agy, Codex, Cursor).

## Overview

TypeScript library for Japanese standard regional mesh codes (JIS X 0410 / 地域メッシュ), supporting first (4 digits), second (6 digits), and third (8 digits) mesh calculations.

## Mandatory Agent Workflow

1. **Keep documentation in sync with code**:
   - `AGENTS.md` is the single source of truth for agent instructions (`CLAUDE.md` imports `@AGENTS.md`).
   - Whenever you add, rename, move, or remove files in `src/` or `scripts/`, npm scripts, or Node.js version settings, update `AGENTS.md` (and `README.md` for user-facing changes) in the same change.
   - Always run `npm run check:docs` and `npm run check:comments` before finishing a task (also enforced automatically via Stop hooks in `.agents/hooks.json`, `.claude/settings.json`, `.codex/hooks.json`, `.cursor/hooks.json` and in CI).
2. **Code comment policy**:
   - Do not add explanatory, inline, or JSDoc comments to source code (avoid injecting unnecessary nuance into AI sessions).
   - Only license headers (e.g. MIT / author) and functionally required toolchain directives (`#!/usr/bin/env node`, `/// <reference ... />`, `/* @vite-ignore */`) are allowed.
3. **PR review comments (e.g. CodeRabbit)**:
   - Always inspect all CodeRabbit (and other reviewer) comments on the PR and decide whether each suggestion is needed or not.
   - Regardless of whether a suggestion is adopted or declined, always react by replying directly to each comment thread:
     - If addressed: thank the reviewer for the catch and briefly note what was changed (including commit SHA).
     - If not addressed: explain clearly why no change is needed.
   - Whenever an AI agent posts a GitHub comment or reply, always include a signature clearly identifying which AI agent generated it (e.g., `— Generated by Antigravity (agy)`, `— Generated by Claude Code`, `— Generated by Codex`, or `— Generated by Cursor`).

## Architecture

- `src/index.ts`: Public exports (`toMeshCode`, `toCenterLatLng`, `toBounds`, `offset`, `scaleFrom`, `SCALES`, `Bounds`, `LatLng`)
- `src/meshCalculator.ts`: Dispatches by mesh code length (4 / 6 / 8 digits, hyphens stripped) or scale (1 / 2 / 3)
- `src/firstMeshCalculator.ts`: 1st mesh (4 digits, ~80km × 80km)
- `src/secondMeshCalculator.ts`: 2nd mesh (6 digits, 8×8 subdivision, digits 0–7)
- `src/thirdMeshCalculator.ts`: 3rd mesh (8 digits, 10×10 subdivision, digits 0–9)
- `src/pointCalculator.ts`: Carry/borrow propagation for hierarchical mesh offsets
- `src/constants.ts`: Max digits per level (`FIRST_MAX_DIGIT = 99`, `SECOND_MAX_DIGIT = 7`, `THIRD_MAX_DIGIT = 9`)
- `src/types.ts`: `LatLng`, `Bounds`, `Point`
- `src/__tests__/`: Unit tests and `fast-check` property-based tests
- `scripts/mutator.mjs`: Diff-driven in-memory Oxc mutation test runner (`scripts/mutator/`)
- `scripts/check-docs-sync.mjs`: Verifies documentation matches repository state
- `scripts/check-no-comments.mjs`: Enforces no explanatory comments in source files
- `scripts/agent-stop-hook.mjs`: Multi-agent Stop hook (`agy`, `claude`, `codex`, `cursor`)

## Conventions

- Formatter / Linter: Biome (`biome.json`)
- TypeScript: `strict: true` (`tsconfig.json`)
- Tests: Vitest (`vitest.config.mts`) with v8 coverage, `fast-check` property-based tests, and in-memory Oxc mutation testing (`oxc-parser`)
- Keep code self-documenting and avoid unnecessary comments
